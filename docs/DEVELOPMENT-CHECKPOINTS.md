## 后续修改与回退原则

1. 新的诊断和修复在检查点之后单独提交，记录复现条件、测试结果及待验证事项。手机未通过的版本不标记为稳定。
2. 源码回看或重建使用检查点标签及独立 Git worktree，避免用破坏性重置覆盖当前工作区。
3. 运行程序需要回退时，先保存正在运行的程序与配置，再从已核验快照或重新构建的检查点部署。Helper-only 回退不替换 Emby 主程序和插件 DLL。
4. 默认保留现有配置、Emby 数据库和原盘文件，不因程序回退覆盖这些数据。设置变更需单独记录和恢复。
5. 上次可播的诊断程序、当前正常程序和未来修复版本分别保存，避免覆盖唯一已验证对照。
