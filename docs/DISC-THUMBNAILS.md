# 原盘章节截图

## 安装与控制

要求 Helper DSM SPK `0.2.0-19` / 同版 Windows 程序，以及 Emby 插件 `0.1.6`。更新 Helper 后，仍需将附带的 DLL 安装到 Emby 数据目录 `plugins` 并重启 Emby。Helper 不擅自改写另一套件的插件目录。

截图适配只处理 BDMV 文件夹和 Blu-ray ISO；DVD ISO、普通 MKV / MP4 不参与。已有有效媒体流、时长和章节时间点是前提。原生章节补全的开关仍只控制时间点写入，不作为截图的额外开关。

| Emby 每媒体库的「生成视频预览缩略图」 | 扫描/刷新元数据 | Emby 原预览缩略图任务成功后 |
|---|---|---|
| 从不 | 不提取 | 不提取 |
| 作为计划任务 | 不提取 | 提取缺失截图 |
| 扫描媒体时及作为计划任务 | 提取缺失截图 | 提取缺失截图 |

`ThumbnailImagesIntervalSeconds=-1` 代表章节标记，生成章节 JPEG；其他间隔按 Emby 规则限制为 1–300 秒，生成 Emby BIF 预览文件。BIF 存储位置遵循 `SaveLocalThumbnailSets`；独立章节 JPEG 与 Emby 原生方式一样保存在内部元数据目录。

Helper「原盘章节」页显示各库截图模式、间隔和补充任务状态。进入页面和手动刷新时读取；只有任务运行且页面可见时刷新进度。不另建截图配置和默认定时器。

Emby 刚启动、编解码器仍在初始化时，HDR 引擎可能暂不可用，此时安全跳过并记录原因。待 Emby 初始化完成后重跑提取任务即可；不能因缩略图字段已有标签就认定图片文件实际可读取。

## 任务与读取方式

Emby 4.10.2 的 `Video.SupportsThumbnails` 对 BDMV / ISO 返回 false，原生任务直接跳过。插件只在原视频预览缩略图任务成功结束后，排队「原盘章节截图（跟随 Emby）」；原任务取消、失败或关闭图片提取均不触发补充。原有任务的时间安排不变，补充任务展示真实进度并可取消。

扫描模式在原生章节提供器之后执行。每部影片先在临时目录生成全部缺图，再检查当前库设置、章节签名、媒体源和时长没有变化，才保存图片关联。已经完成的影片保留；中断或失败可重试缺失部分。不删除用户已有 JPEG、自定义章节名称、时间点或片头尾标记。关闭截图设置不会清除历史图片。

`--helper-thumbnail-session` 只返回选定正片的可定位片段。BDMV 直接读取实际 M2TS；ISO 使用现有 UDF 随机读取，通过随机 loopback HTTP Range URL 提供片段，生命周期仅限本次会话。不解压整盘，不 remux，不重新编码整部影片。截图需要解码少量视频帧并编码成小 JPEG，不改变原片或播放方式。

多片段按 MPLS 时间线、播放裁剪区间及 CLPI presentation start 映射 seek。正片版本不匹配、导航不完整或多个时钟域时明确报错，避免给章节关联错误画面。当前明确选择主分辨率视频流，显式 `-map`，避免误选 1080p 杜比增强层。

M2TS 任意位置快速 seek 可能先遇到引用帧不完整的 open-GOP，产生马赛克截图。适配层通过原生提取器的 protected 输入参数扩展，增加 `-skip_frame nokey`，选择定位附近的可用关键帧；章节时间点保持不变，预览画面可能略晚于该时间点。该扩展仅创建独立子类，不替换或修改 Emby 已加载的方法。接口不兼容时明确失败。

## HDR 与杜比视界颜色

输出是供常规浏览器/客户端显示的 **SDR JPEG**。HDR10、HDR10+、支持的杜比视界兼容底层都必须经过实际 HDR → SDR 色调映射，不能把 PQ 像素直接写入 JPEG，也不能仅靠提高饱和度冒充色调映射。

使用 Emby 当前配置的原版 ffmpeg、原生截图引擎、线程数、色调映射算法与环境。运行前检查引擎实际生成的色调映射滤镜；引擎不具备适用滤镜、禁用了色调映射、选择 `none` 或 HDR 传递函数缺失时，跳过并保留旧图，日志给出原因。

对已验证的双层 Dolby Vision Profile 7 原盘，选择 4K HDR10 兼容底层，经 Emby `supertonemap` 生成 SDR 预览，不使用 1080p 增强层。这不等同于完整重建 Dolby Vision RPU / FEL 动态画面；HDR10+ 预览也不保证使用其动态元数据。正常色彩的预览不影响原片的 HDR / DV 播放。

没有确认兼容底层的杜比视界（如 Profile 5）不生成紫绿偏色图。HLG 需要原生截图引擎提供相应映射；当前验证的 Emby 4.10.2 引擎仅对 PQ 启用 `supertonemap`，因此 HLG 会清晰失败，不宣称已支持。SDR 不重复应用 HDR 映射。

日志 `DiscThumbnails` 包含影片 ID、播放列表、截图数、视频流索引、尺寸、色彩传递函数、实际色调映射滤镜、保存结果或失败原因。诊断时在 Emby 日志中检索该关键字。

## 平台与维护

- 插件 `Thumbnails/`：Emby 库设置策略、扫描提供器、原任务完成监听、进度任务、图片合并以及原生截图引擎兼容层。
- `ProbeWrapper/Thumbnails/DiscThumbnailSession.cs`：跨平台导航及按需输入；`IsoMediaHttpSource` 提供限时、随机 URL 的只读 Range 流。
- Helper `Chapters/` / Web `chapters.js`：只读设置与任务展示，不接管 Emby 调度。

Emby 账号必须能执行截图读取器、读取原盘和写入 Emby 元数据目录；启用本地 BIF 保存时还必须能写对应媒体目录。DSM 使用 SPK 内 `probe.sh`，沿用已有 Emby 运行环境。容器中的读取器与媒体路径必须对 Emby 进程可见，loopback 流在其网络命名空间内创建。

原生截图实现的版本差异在单独兼容层中检测，不兼容时明确失败；不修改 Emby DLL、私有配置或视频文件。DSM / Docker / 其他 Emby 版本仍需各自环境实测，不能用 Windows 成功替代真机验证。

章节图片从 Emby API 返回且 Emby 中可用，不保证每个第三方客户端都展示这些章节图片。另一个独立限制是 Emby 4.10.2 的 `Items/{id}/ThumbnailSet` / BIF 下载接口仍会按原盘类型返回空集合；本功能没有绕过这些接口，不能据 BIF 文件存在宣称播放器拖动进度条的预览已经支持。固定间隔 BIF 用于原生章节图片读取，章节标记模式使用独立 JPEG。

## 本机验证（2026-11-01）

Windows Emby 4.10.2.0，插件 0.1.6：

| 影片 | 来源与色彩 | 章节 JPEG | 截图阶段耗时 |
|---|---|---|---|
| 碧海蓝天 | BDMV，DV Profile 7 / HDR10 | 16 | 约 10 秒 |
| 布达佩斯大饭店 | BDMV，DV Profile 7 / HDR10 | 18 | 约 22 秒 |
| 奇异博士 2 | 三片段 BDMV，HDR10 | 29 | 约 17 秒 |
| 青蛇 | ISO，1080p SDR | 20 | 约 12 秒 |
| 禁闭岛 | ISO，DV Profile 7 / HDR10 | 20 | 约 44 秒 |
| 傲慢与偏见 | BDMV，DV Profile 7 / HDR10 | 16 | 约 12 秒 |

均等待 Emby 最终刷新提交完成后读取 API：章节图片标签完整，章节名称、时间点、媒体源和音视频流保持一致。实际读取图片并人工检查代表画面，不只检查日志或文件是否存在。HDR10 / DV 日志确认 `supertonemap=tonemap=hable`，SDR 未重复色调映射。open-GOP 马赛克在关键帧模式下消除；没有把被黑场覆盖的某一张图当成色彩验证证据。

另外实测「从不」「仅计划任务」下单片刷新不提取，禁用库任务跳过，补充任务进度和取消正常；任务取消前后本机全部电影的媒体字段保持一致。固定间隔 BIF 格式、图片数量及章节图片 HTTP 读取已验证；拖动预览接口的限制如上。

WSL 验证了非特权 Linux 用户的截图导航协议、EOF 退出、SPK 结构和分账号套件生命周期。未在本轮自动升级 NAS 109，DSM 原版 ffmpeg 色调映射和原生提取器仍需真机验证。HDR10+ 动态元数据、其他 DV profile、HLG 未以真实原盘验证，不宣称支持完整动态映射。
